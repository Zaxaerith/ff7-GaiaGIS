# GaiaGIS v5.18.0 — Local Spatial Database Query Service

## What's New

- Add an optional local HTTP query service for one previously exported FieldLocal GeoPackage v3. It reuses Python's `ThreadingHTTPServer` and standard-library `sqlite3` to connect the browser, HTTP API, relational database, and JSON result tables without another database server or Web framework.
- Provide fixed GET endpoints at `/__gaiagis_local__/db/status`, `/__gaiagis_local__/db/events`, and `/__gaiagis_local__/db/controls`. Queries use parameterized `SELECT` and `JOIN` statements, bounded result sizes, stable pagination, and explicit complete, partial, or unavailable states. Optional relationships are returned as JSON `null`.
- Query Field script events with optional Gameplay and Dialogue references, and filter conditional-control evidence by standard, strong, or core level. Original Field and instruction identities are retained. Control rows remain root-specific static evidence, not deduplicated event counts or runtime execution claims.
- Add Local Spatial Database Query to Data & Settings. The interface reports the request path, HTTP status, returned row count, and request round-trip time; this timing is not isolated SQL execution time. It supports the five existing UI languages and responsive layouts, keeps private results in the current session, and clears stale results after Workspace replacement.

## Source Validation and Security

- Restrict service access to the existing loopback HTTP environment with validated Host and Origin headers and a dedicated database request header. Same-origin Fetch is used without permissive CORS.
- Accept only explicitly configured local GeoPackage v3 files in the supported private export directory. Validate schema, Field identity, source fingerprints, and evidence-channel status.
- Use read-only SQLite connections and fixed parameterized queries. Arbitrary SQL, file paths, mutation requests, and changed database files are rejected. Query execution, concurrency, pagination, and response sizes are bounded.
- Keep private databases outside the HTTP static-asset allowlist and all public distributions. Structural validation and source matching do not independently authenticate arbitrary externally modified evidence.

## Existing Workspace Serving

The source-checkout CLI can serve an existing verified Workspace without rebuilding game-derived assets:

```text
python -m gaiagis local --serve-existing --workspace output/local-workspace --field-db output/exports/fieldlocal/example-v3.gpkg --port 5180
```

`example-v3.gpkg` is a placeholder for a previously exported and validated private database. Database configuration is optional; the Viewer remains available without it. This mode refuses pending Field CFG recovery transactions. The database validation workflow requires SQLite 3.37 or newer.

## Compatibility and Distribution

- No Workspace asset, Manifest migration, or new GeoPackage format is introduced. Existing spatial analysis and evidence semantics are preserved.
- Public Pages remain a static source-only Viewer and do not probe localhost for this service. Database querying is an optional source-checkout CLI workflow; the Windows portable GUI retains its existing launch behavior.
- Users provide legally obtained original FF7 data for private Workspace features. The private course-demonstration database and complete query results are not distributed.

## Known Limitations

- One explicitly selected FieldLocal GeoPackage v3 is supported at a time, with fixed read-only queries only. There is no general SQL editor, CRUD, database administration, multi-user, remote, or LAN service.
- No global Field coordinate registration or inferred event positions are added. Original dialogue bodies are not distributed.
