# GaiaGIS v5.16.0 — Field Evidence GIS Export

## FieldLocal GeoPackage v3

- Add explicit version 3 export through the existing source CLI. Preserve all 19 FieldLocal v2 tables and add 18 standard GeoPackage attribute tables, for 37 data tables: seven spatial layers and 30 nonspatial attribute tables.
- Preserve original FieldLocal XYZ coordinates, raw4 attributes, directed Access records, Entrances, Gateways, and original Interaction geometry.
- Retain the v1 and v2 export contracts; v1 remains the default format.

## Script and Gameplay Evidence

- Export original Actor, Entry root, alias, instruction, and ownership identities alongside Gameplay events, Dialogue references, conditional control relations, ASK local-address evidence, and one-hop REQ target relations.
- Preserve standard, strong, and core conditional evidence as distinct ownership scopes. Keep Gameplay and Dialogue evidence nonspatial.
- Distinguish same-Actor and same-Entry associations from original LINE geometry and exact surface contact. Preserve unavailable, rejected, limited, and unknown states.
- Export Dialogue reference identities and metadata without original dialogue text.

## Shared Production Analysis

- Reuse the existing TypeScript conditional-evidence analyzer through a controlled local Node subprocess instead of duplicating the strict control-dependence algorithm in Python.
- Validate versioned internal exchange data, source identities, natural keys, relation completeness, and analysis status before publication. Arbitrary external JSON is not accepted as trusted strict evidence.
- Use bounded subprocess execution, transactional database writing, and source revalidation.

## QGIS Research Integration

- Provide an optional single-Field QGZ research project with Geometry, Interaction, Gameplay, Dialogue, and Conditional Evidence layer groups.
- Include 11 predefined QGIS relations for source geometry, contact candidates, script ownership, conditional controls, and request targets. GeoPackage paths are relative.
- The validated reference project loads 38 layers and attribute-table entries, including an additional filtered LINE-contact layer; its database contains 37 data tables.
- Database validation uses SQLite and OGR; QGIS loading and project relocation were also validated.

## Compatibility Fix

- Correct FieldLocal v2 export metadata to report the actual validated Interaction container version instead of an unconditional version 1 value. Geometry, fields, and source semantics are preserved; existing GeoPackages are not automatically modified or migrated.
- Reuse existing Workspace assets without new mandatory files or Manifest migration. Existing Web Viewer and source-only Pages functionality remain available.

## Requirements and Distribution

- The optional source-checkout CLI exporter requires a compatible local Node and GDAL-enabled Python environment. Optional QGZ creation requires the existing PyQGIS environment.
- The Windows portable distribution remains lightweight and does not bundle Node, GDAL, or PyQGIS for this research exporter.

## Known Limitations

- Each export represents one Field in its independent FieldLocal coordinate space. Undefined Cartesian SRS `-1` is retained; raw units are not physical metres.
- QGIS relation browsing does not establish event coordinates, runtime script execution, or gameplay accessibility. Same-Actor and same-Entry relations are evidence associations, not proven event positions.
- ASK local relations do not prove actual player answers. REQ target events do not inherit conditional control from their request source.
- This release does not add global Field registration, a multi-Field spatial database, runtime simulation, or encounter-route export.
